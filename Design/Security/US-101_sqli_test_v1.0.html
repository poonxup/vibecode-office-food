สถานะการดำเนินการ: สำเร็จ 16/16

ข้อเสนอแนะ

  1. SQLI-06 (Low): error ของ PostgREST เผยชื่อคอลัมน์/ชนิดข้อมูล เป็นพฤติกรรมมาตรฐานของ PostgREST ลดผลกระทบได้โดยไม่เปิด schema ที่ไม่จำเป็น และถือว่าโครงสร้างตารางที่อ่านได้เป็นข้อมูลสาธารณะ ตรวจซ้ำด้วยการส่งคอลัมน์ผิดแล้วดูว่ายังตอบ 400 เท่าเดิม
  2. AUTHZ-01 (Low): ถ้าเมนู is_available=false ถือเป็นความลับทางธุรกิจ ให้แก้ policy เป็น using (is_available) เพื่อไม่ให้ anon เห็นแถวที่ซ่อน ตรวจซ้ำด้วย C2 ว่าคืน []
  3. AUTHZ-02 (Low): categories/menu_item_categories ยังไม่ถูกใช้ใน US-101 ถ้ายังไม่จำเป็น ให้ปิด policy SELECT ของ anon หรือยกออกจาก schema ที่เปิด ตรวจซ้ำด้วย D1 ว่าคืน 401/[]

สรุป: ไม่พบช่องโหว่ SQL injection ทุก payload ถูก PostgREST parameterize หรือถูก Cloudflare WAF บล็อก และ anon เขียนข้อมูลไม่ได้ทุกวิธี (INSERT/UPDATE/DELETE/UPSERT = 401) ข้อบกพร่องที่พบเป็นระดับ Low ด้านการเปิดเผยข้อมูล/พื้นผิว ไม่มี Critical/High/Medium
