WSR-06 การเปลี่ยนเส้นทาง http:// ไป https:// (บทบาท: ผู้ใช้ทั่วไป) WSTG-CONF-07 (หมวด); NIST SP 800-115 §4 ขอหน้าแรกผ่าน HTTP แล้วอ่านสถานะและ Location ส่งคำขอ http://vibecode-office-food.vercel.app/ จากเครือข่ายเครื่องตรวจ 2 ครั้งในรอบนี้ ตรวจไม่สำเร็จ ยังยืนยันไม่ได้: ได้ HTTP 500 จาก Server: Pingora ที่ที่อยู่ 198.18.0.1 ซึ่งน่าจะเป็นพร็อกซีขาออกของสภาพแวดล้อมตรวจ ไม่ใช่ขอบของ Vercel โดยตรง จึงยืนยันการเปลี่ยนเส้นทาง 301/308 ของโดเมนจริงจากเครือข่ายนี้ไม่ได้ ข้อนี้อยู่ในรายงานเดิม S-02 / R-08 (19 พ.ย. 2026, Production) ด้วยผลเดียวกัน อย่างไรก็ตามมี HSTS (ดู WSR-07) และชื่อ *.vercel.app อยู่ในรายการ HSTS preload ของเบราว์เซอร์ จึงบังคับ HTTPS ได้หลังเข้าครั้งแรกหรือจาก preload คำตอบ HTTP/1.1 500 Internal Server Error, Server: Pingora, Content-Length: 0; การเชื่อมต่อไปที่ 198.18.0.1:80; อ้างรายงาน US-101_security_findings_v1.0 และ v1.1 รายการ S-02 / R-08 วันที่ 19 พ.ย. 2026 สภาพแวดล้อม Production ไม่มี (ข้อจำกัดของหลักฐาน) ตรวจซ้ำจากเครือข่ายอื่นที่ออกอินเทอร์เน็ตตรง ว่า http:// ได้ 301/308 ไป https:// แล้วค่อยปิดข้อนี้ ส่งต่อเป็นข้อจำกัดของหลักฐาน ไม่ใช่ข้อบกพร่องที่ยืนยันได้ หาก 201/202 ตรวจจากเครือข่ายอื่นได้ผล redirect ให้แจ้งกลับมาอัปเดต
WSR-07 HSTS ของหน้าเว็บและไฟล์ static (บทบาท: ผู้ใช้ทั่วไป) WSTG-CONF-07; WSTG-CRYP-03 (หมวด) อ่าน response header จากหน้าเว็บตามปกติ อ่าน header ของ /, /index.html, /js/app.js, /js/config.js, /styles.css และเอกสารใน /Design/ ตรวจสำเร็จ ผ่านในขอบเขตที่ตรวจ: ทุกเส้นทางที่ตรวจมี Strict-Transport-Security: max-age=63072000; includeSubDomains; preload ตามที่กำหนดใน vercel.json สอดคล้องผลเดิม S-03 (ปิด/ผ่านตั้งแต่ v1.0) และยังคงอยู่บน v1.0.2 header บน Production วันที่ 19 พ.ย. 2026; vercel.json ชุด header ของ /(.*) ไม่มี ไม่ต้องแก้ —

WSR-12 การบังคับใช้ is_available ฝั่งเซิร์ฟเวอร์ ของตาราง menu_items (บทบาท: anon) WSTG-ATHZ-01; WSTG-ATHZ-02; OWASP API1 Broken Object Level Authorization; OSSTMM (การควบคุมที่สังเกตได้) ทบทวนนโยบาย RLS, โค้ดไคลเอนต์, User Story และผลรายงานเดิม ไม่ทดลองข้ามสิทธิ์ด้วยการเรียกแถวที่ซ่อนผ่าน REST ในรอบนี้ อ่านนโยบาย menu_items_read จากคลังและจาก pg_policies วันนี้ (qual=true) อ่าน js/app.js ที่กรอง is_available=eq.true เฉพาะตอนเรียกของหน้าเว็บ อ่าน User Story ที่กำหนดว่าเมนู is_available=false ต้องไม่แสดง และอ้างรายงาน US-101_sqli_test_v1.0 รายการ AUTHZ-01 (19 พ.ย. 2026, Production v1.0.2) รวมถึงรายงาน v1.0 รายการ S-13 ที่บันทึกข้อสังเกตไว้แล้ว นับจำนวนแถวแบบรวมจาก SQL อ่านอย่างเดียว (ไม่ดึงเนื้อหาแถวที่ซ่อน) ตรวจสำเร็จ พบข้อบกพร่องที่ยืนยันได้: นโยบาย RLS ใช้ using (true) จึงอนุญาตให้บทบาท anon อ่านได้ทุกแถว รวมแถวที่ is_available=false หน้าเว็บกรองเฉพาะฝั่งคำขอของไคลเอนต์ ผู้ที่เรียก REST โดยตรงด้วย publishable key จึงมองเห็นเมนูที่ UI ซ่อนได้ ฐานข้อมูลวันนี้มี 12 แถว มีขาย 10 ซ่อน 2 ผลกระทบจำกัดเพราะเป็นข้อมูลเมนูม็อกสาธารณะ ไม่ใช่ข้อมูลส่วนบุคคล แต่ไม่สอดคล้องกับเจตนาของ User Story ที่ต้องการไม่แสดงเมนูที่งดขาย และไม่มีชั้นบังคับใช้ฝั่งเซิร์ฟเวอร์ pg_policies วันนี้: policy menu_items_read, roles {{anon,authenticated}}, cmd=SELECT, qual=true; js/app.js บรรทัดเรียก is_available=eq.true; US-101_user_story.md (เมนูที่ is_available=false ต้องไม่แสดง); รายงาน US-101_sqli_test_v1.0.html รายการ AUTHZ-01 วันที่ 19 พ.ย. 2026 สภาพแวดล้อม Production v1.0.2 (ผลจากรายงานเดิม ไม่ได้ยิงคำขอซ้ำเพื่ออ่านแถวที่ซ่อนในรอบนี้); SELECT นับแถววันนี้ hidden_count=2 Low ปรับนโยบายเป็น using (is_available = true) สำหรับ anon (และ authenticated ถ้ายังไม่ต้องการให้เห็นของซ่อน) หรือแยกนโยบายตามบทบาทผู้ดูแล วิธียืนยัน: หน้าเว็บยังโหลดเมนูที่มีขายครบ 10 รายการ; คำขอ GET แบบผู้ใช้ทั่วไปโดยไม่ใส่ตัวกรองต้องไม่คืนแถว is_available=false; Security Advisor ยังไม่มีรายการใหม่ที่ผิด ส่งต่อ 202 ให้แก้ RLS แล้วให้ 203 ตรวจซ้ำพฤติกรรมหน้าเว็บและสัญญา API แบบอ่านตามที่ได้รับอนุญาต
WSR-13 การอ่านตาราง categories และ menu_item_categories (บทบาท: anon) WSTG-ATHZ-01; OWASP API1 / API5; OSSTMM ทบทวนนโยบาย RLS และสิทธิ์จากแคตตาล็อก รวมผลรายงานเดิม ไม่ดึงข้อมูลทั้งตารางผ่าน REST ในรอบนี้ สอบถาม pg_policies และ role_table_grants วันนี้ อ่าน db/001 ที่ระบุว่า US-101 ยังไม่ใช้ตารางเหล่านี้ และอ้างรายงาน US-101_sqli_test_v1.0 รายการ AUTHZ-02 (19 พ.ย. 2026, Production v1.0.2) ตรวจสำเร็จ พบข้อบกพร่องที่ยืนยันได้: anon มี GRANT SELECT และนโยบาย SELECT using (true) ทั้งตาราง categories และ menu_item_categories ทั้งที่หน้าเว็บ US-101 ไม่ได้ใช้ ข้อมูลไม่ใช่ความลับทางธุรกิจในชุดม็อก แต่เป็นพื้นผิว API ที่เปิดเกินความจำเป็น (least privilege) pg_policies วันนี้: categories_read และ menu_item_categories_read, qual=true, cmd=SELECT, roles anon/authenticated; grants เหลือ SELECT; db/001 ระบุ US-101 ยังไม่ใช้; รายงาน SQLi v1.0 รายการ AUTHZ-02 วันที่ 19 พ.ย. 2026 Production v1.0.2 (ผลจากรายงานเดิม) Low REVOKE SELECT ของ anon/authenticated บนตารางที่ UI ยังไม่ใช้ หรือเปลี่ยนนโยบายให้ไม่เปิดอ่านจนกว่าจะมีสตอรีที่ต้องใช้ วิธียืนยัน: GET /rest/v1/categories และ /rest/v1/menu_item_categories ด้วย publishable key ต้องถูกปฏิเสธ ส่วน GET เมนูของหน้าเว็บยังได้ 200 ส่งต่อ 202 ให้ลดสิทธิ์อ่านตารางที่ยังไม่ใช้ แล้วให้ 203 ตรวจซ้ำว่าหน้าเมนูยังทำงาน
WSR-14 IDOR และแยกข้อมูลระหว่างองค์กรหรือระหว่างผู้ใช้ WSTG-ATHZ-02; OWASP API1 BOLA ทบทวนโมเดลข้อมูลและฟังก์ชันที่มี อ่าน Design/Data_Model.md, db/001 และ User Story ไม่พบตารางคำสั่งซื้อ บัญชีผู้ใช้ใน schema ที่แอปใช้ หรือตัวระบุทรัพยากรรายบุคคล ตรวจสำเร็จ ไม่เกี่ยวข้อง: ในขอบเขต US-101 ไม่มีข้อมูลที่เป็นของแต่ละผู้ใช้หรือแต่ละองค์กร ไม่มีรหัสคำสั่งซื้อหรือเอกสารส่วนตัวให้ทดสอบ IDOR การแยกสิทธิ์ระหว่างองค์กรจึงยังไม่มีวัตถุให้ตรวจ ข้อที่เกี่ยวกับการอ่านแถวเมนูที่ซ่อนบันทึกไว้แล้วที่ WSR-12 Data_Model.md และ db/001 มีเพียง menu_items, categories, menu_item_categories; ตะกร้าไม่ถูกบันทึกในฐานข้อมูล ไม่มี เมื่อมีสตอรีคำสั่งซื้อหรือข้อมูลรายผู้ใช้ ให้ตรวจ BOLA/IDOR ใหม่ทั้งฝั่งเซิร์ฟเวอร์ —
05. Session Management และ CSRF
WSR-15 Cookie ของโดเมนแอปและโดเมน API (บทบาท: ผู้ใช้ทั่วไป) WSTG-SESS-02; WSTG-CLNT (หมวด) สังเกต Set-Cookie จากคำตอบของหน้าเว็บตามปกติและจาก GET API ที่แอปใช้ อ่าน header ของ https://vibecode-office-food.vercel.app/ และของ GET เมนูบน supabase.co ไม่ได้คัดลอกค่าคุกกี้มาไว้ในรายงาน ตรวจสำเร็จ ผ่านในขอบเขตที่ตรวจ: โดเมนแอป (Vercel) ไม่ตั้ง Set-Cookie เลย คุกกี้ที่พบมีเพียงคุกกี้ของ Cloudflare ฝั่ง supabase.co ชื่อ __cf_bm ซึ่งมีคุณสมบัติ Secure, HttpOnly, SameSite=None, Partitioned, Path=/, Domain=supabase.co ใช้เพื่อบริหารบอต ไม่ใช่เซสชันของผู้ใช้แอป ค่าคุกกี้ถูกปกปิดในรายงานนี้ header หน้าแรกของ Vercel ไม่มี Set-Cookie; header GET เมนูของ Supabase มี __cf_bm พร้อมคุณสมบัติที่ระบุ (ไม่บันทึกค่า) ไม่มี ไม่ต้องแก้ —
WSR-16 อายุเซสชันและการยกเลิกเซสชันเมื่อ Logout WSTG-SESS-06; WSTG-SESS-07 ทบทวนฟังก์ชันที่มีจริง สำรวจหน้าเว็บและโค้ด ไม่มีสถานะล็อกอินหรือปุ่มออกจากระบบ ตรวจสำเร็จ ไม่เกี่ยวข้อง: ไม่มีเซสชันผู้ใช้ให้หมดอายุหรือยกเลิกเมื่อ Logout ในขอบเขต US-101 ไม่มีโค้ดจัดการเซสชันใน js/; ดู WSR-10 ไม่มี เมื่อมีล็อกอิน ให้ตรวจอายุเซสชัน การหมดอายุฝั่งเซิร์ฟเวอร์ และการทำลายเซสชันตอนออกจากระบบ —
WSR-17 การป้องกันคำขอเปลี่ยนข้อมูลจากเว็บไซต์อื่น (CSRF) WSTG-SESS-05; OWASP API (ด้านคุ้มครองคำขอเปลี่ยนข้อมูล) ทบทวนลักษณะคำขอที่แอปใช้และความสัมพันธ์กับคุกกี้ อ่าน js/app.js และ js/cart.js รวมผลสิทธิ์เขียนจาก WSR-11 การเปลี่ยนข้อมูลในแอปมีเพียงสถานะตะกร้าในหน่วยความจำ ไม่มีคำขอ POST/PATCH/DELETE จากหน้าเว็บ ตรวจสำเร็จ ผ่านในขอบเขตที่ตรวจ: หน้าเว็บไม่ส่งคำขอเปลี่ยนข้อมูลไปเซิร์ฟเวอร์ และไม่มีคุกกี้เซสชันบนโดเมนแอป การเรียก API ใช้หัว Authorization (ไม่ถูกส่งอัตโนมัติจากฟอร์มข้ามไซต์) สิทธิ์เขียนของ anon ถูกถอนแล้วจึงไม่มีฟังก์ชันเปลี่ยนข้อมูลให้โจมตีด้วย CSRF ในขอบเขตนี้ js/app.js มีเพียง fetch แบบ GET; ไม่มี Set-Cookie บนโดเมนแอป; grants เหลือ SELECT (WSR-11) ไม่มี เมื่อมีคำขอเปลี่ยนข้อมูลที่อาศัยเซสชันหรือคุกกี้ ให้ใส่การป้องกัน CSRF ที่เหมาะสมแล้วตรวจซ้ำ —
06. SQL Injection
WSR-18 โค้ดไคลเอนต์และการเรียก PostgREST ของหน้าเมนู (บทบาท: ผู้ใช้ทั่วไป) WSTG-INPV-05; NIST SP 800-115 §4 ทบทวนโค้ดที่นำค่าไปใช้กับฐานข้อมูล อ่าน js/app.js ทั้งไฟล์ ค้นหาการประกอบ SQL หรือเรียก RPC จากคลังแอป ตรวจสำเร็จ ผ่านในขอบเขตที่ตรวจ: หน้าเว็บไม่ได้ประกอบคำสั่ง SQL เอง การอ่านเมนูใช้ URL ของ PostgREST ที่ค่าตัวกรองถูกกำหนดคงที่ในโค้ด (is_available=eq.true และลำดับคอลัมน์คงที่) ไม่มีช่องค้นหา ล็อกอิน หรือรายงานที่รับอินพุตผู้ใช้ไปต่อกับ SQL ในแอปนี้ js/app.js ฟังก์ชัน loadMenu(); ไม่พบคำว่า SQL, rpc, หรือการต่อสตริงคำสั่งฐานข้อมูลใน js/ ไม่มี ไม่ต้องแก้ในโค้ดปัจจุบัน หากเพิ่มค้นหา/กรองจากอินพุตผู้ใช้ ให้คงการใช้ตัวกรองของ PostgREST หรือพารามิเตอร์ที่ถูกผูกค่า และห้ามต่อสตริง SQL —
WSR-19 ชั้น PostgREST / ฐานข้อมูลเมื่อได้รับอินพุตที่อาจเป็นคำสั่ง SQL (หลักฐานจากรายงานเดิม) WSTG-INPV-05; PTES Vulnerability Analysis; NIST SP 800-115 §4 ทบทวนผลตรวจเชิงรุกที่ได้รับอนุญาตก่อนหน้า ไม่ยิง payload ซ้ำในรอบนี้ อ่านรายงาน US-101_sqli_test_v1.0.html ทั้งฉบับ (วันที่ 19 พ.ย. 2026, Production web v1.0.2, ข้อมูลม็อก) ซึ่งเจ้าของระบบเคยอนุญาตให้ทดสอบเชิงรุกในขอบเขตที่กำหนด รอบทบทวนนี้เป็นแบบสังเกตเท่านั้น จึงไม่ส่ง payload และไม่เรียกคำสั่งเขียน ตรวจสำเร็จ ผ่านในขอบเขตที่ตรวจ: ตามรายงานเดิม ยิง 16 รายการแล้วไม่พบช่องโหว่ SQL injection ค่าที่ส่งผ่านตัวกรองของ PostgREST ถูกทำให้เป็น literal หรือถูกบล็อกที่ขอบ (Cloudflare WAF ของ Supabase, 403) ไม่มีคำสั่งไปรันในฐานข้อมูล การเขียนทุกวิธีถูกปฏิเสธและชุดข้อมูลม็อกไม่เปลี่ยน ข้อสรุปนี้เป็นการอ้างผลรายงานเดิม ไม่ได้ทำซ้ำในรอบเชิงสังเกต รายงาน Design/Security/US-101_sqli_test_v1.0.html วันที่ 19 พ.ย. 2026 สภาพแวดล้อม Production v1.0.2 (ผลจากรายงานเดิม) รายการเกี่ยวกับ payload คลาสสิก, UNION, stacked, boolean และสรุปว่าไม่พบ SQLi ไม่มี ไม่ต้องแก้ในประเด็น SQL injection ตามหลักฐานที่มี คงการใช้ PostgREST / ค่าที่ถูกผูก และอย่าเปิด raw SQL ให้ผู้ใช้ —
07. Cross-Site Scripting (XSS)
WSR-20 การสะท้อนข้อมูลจากที่อยู่หรืออินพุตทันทีบนหน้าแรก (บทบาท: ผู้ใช้ทั่วไป) WSTG-INPV-01 ทบทวนโค้ดว่ามีการนำค่าจาก URL หรืออินพุตผู้ใช้ไปแสดงทันทีหรือไม่ อ่าน js/app.js และ index.html ทั้งไฟล์ ค้นหา location, search, hash, innerHTML ที่เกี่ยวกับอินพุตผู้ใช้ ตรวจสำเร็จ ผ่านในขอบเขตที่ตรวจ: ไม่มีช่องอินพุตและโค้ดไม่ได้อ่านค่าจาก query string หรือ fragment ไปแสดงผล จึงไม่พบพื้นผิว XSS แบบสะท้อนในหน้านี้ js/app.js ไม่พบ location.search / URLSearchParams / document.write; หน้าเว็บไม่มีฟอร์ม ไม่มี หากเพิ่มช่องค้นหาหรือการอ่านพารามิเตอร์จาก URL ต้องเข้ารหัสตามบริบทก่อนแสดงผลแล้วตรวจซ้ำ —
WSR-21 การแสดงข้อมูลเมนูที่มาจากฐานข้อมูล (XSS แบบบันทึก บทบาท: ผู้ใช้ทั่วไป) WSTG-INPV-02; WSTG-CLNT-01 (หมวด) ทบทวนการเข้ารหัสตอนแสดงผลและสิทธิ์การเขียนข้อมูล อ่านฟังก์ชัน esc(), renderMenu(), renderSummary() และ showMenuState() ใน js/app.js รวมสิทธิ์เขียนจาก WSR-11 ข้อสังเกตเรื่อง onerror แบบ inline ในรายงาน v1.0 รายการ S-16 ถูกแก้แล้วใน v1.0.2 ตรวจสำเร็จ ผ่านในขอบเขตที่ตรวจ: ค่าจากฐานข้อมูลที่นำไปประกอบ HTML (id, ชื่อ, หมวด, ราคา, image_url, ข้อความผิดพลาด) ผ่านฟังก์ชัน esc() ซึ่งแปลง &, &lt;, &gt;, เครื่องหมายคำพูด และเครื่องหมายอะพอสทรอฟี ก่อนใส่ innerHTML ผู้ใช้ทั่วไปเขียนข้อมูลเมนูไม่ได้ (WSR-11) ข้อสังเกต S-16 เรื่องตัวจัดการ onerror แบบ inline ถูกย้ายเป็น addEventListener ใน v1.0.2 เพื่อให้เข้ากับ CSP ที่ไม่อนุญาตสคริปต์ในบรรทัด และตรวจพบในโค้ดที่เสิร์ฟวันนี้แล้ว image_url ถูกใส่ในแอตทริบิวต์ src หลัง escape และถูกจำกัดเพิ่มด้วย CSP img-src 'self' https: data: js/app.js ฟังก์ชัน esc และจุดที่เรียกใช้; ตัวจัดการ error ของรูปที่ menu-grid; รายงาน v1.0 รายการ S-16 และโค้ดคอมเมนต์ S-04/S-16 ใน v1.0.2; CSP บน Production ไม่มี ไม่ต้องแก้ในขอบเขตปัจจุบัน คงการใช้ esc() กับทุกค่าที่ประกอบ HTML และอย่าใส่สคริปต์ในบรรทัด —
WSR-22 การประกอบ DOM จากสถานะตะกร้าในเบราว์เซอร์ (บทบาท: ผู้ใช้ทั่วไป) WSTG-CLNT-01 ทบทวนการแสดงผลจากสถานะฝั่งไคลเอนต์ อ่าน renderSummary() และ addItem() จำนวนสินค้าถูกเพิ่มเป็นจำนวนเต็มในโค้ด ไม่ได้อ่านจากอินพุตอิสระ ตรวจสำเร็จ ผ่านในขอบเขตที่ตรวจ: รายการในสรุปใช้ชื่อและราคาที่ผ่าน esc() จำนวน (qty) มาจากการนับใน addItem() ซึ่งเพิ่มขึ้นทีละ 1 จากค่าเริ่ม 1 ไม่พบการใช้ eval หรือ document.write js/cart.js addItem(); js/app.js renderSummary() ไม่มี ไม่ต้องแก้ —

WSR-23 Command Injection และ Template Injection WSTG-INPV-11; WSTG-INPV-18 (หมวด) ทบทวนฟังก์ชันที่อาจส่งค่าไปเชลล์หรือเทมเพลตฝั่งเซิร์ฟเวอร์ ทบทวนสถาปัตยกรรม: หน้าเว็บเป็นไฟล์คงที่บน Vercel ไม่มีเซิร์ฟเวอร์ประมวลผลคำสั่งหรือเรนเดอร์เทมเพลตตามอินพุตผู้ใช้ ส่วนหลังบ้านที่แอปเรียกคือ PostgREST สำหรับอ่านเมนูเท่านั้น ตรวจสำเร็จ ไม่เกี่ยวข้อง: ไม่มีฟังก์ชันสร้างเอกสาร ประมวลผลคำสั่งระบบ หรือเทมเพลตฝั่งเซิร์ฟเวอร์ที่รับอินพุตผู้ใช้ในขอบเขต US-101 คลังเป็นไฟล์คงที่ (index.html, js, css) ไม่มี API เซิร์ฟเวอร์ของแอปเอง; vercel.json มีแต่ headers ไม่มี เมื่อมีฟังก์ชันสร้างเอกสารหรือเรียกคำสั่งระบบ ให้ตรวจหมวดนี้ใหม่ —
WSR-24 Path Traversal ของเส้นทางไฟล์บนโดเมนแอป WSTG-ATHZ-01 (หมวดไฟล์); WSTG-CONF-05 ทบทวนว่ามีพารามิเตอร์เส้นทางไฟล์หรือไม่ และตรวจเส้นทางอ่อนไหวที่ทราบ อ่านโค้ดแล้วไม่พบพารามิเตอร์ชื่อไฟล์จากผู้ใช้ ตรวจ HEAD เส้นทางอ่อนไหวที่ทราบ (.git, .env, db/) ได้ 404 ตรวจสำเร็จ ผ่านในขอบเขตที่ตรวจ: แอปไม่รับเส้นทางไฟล์จากผู้ใช้ไปเปิดบนเซิร์ฟเวอร์ ไฟล์ถูกเสิร์ฟแบบคงที่ เส้นทางภายในที่ตรวจแล้วไม่ถูกเปิด ไม่มีพารามิเตอร์ไฟล์ใน js/; HEAD /.git/HEAD และ /.env และ /db/ ได้ 404 ไม่มี ไม่ต้องแก้ —
WSR-25 SSRF การให้เซิร์ฟเวอร์ดึง URL ตามผู้ใช้ WSTG-INPV-19; OWASP API (หมวด SSRF ที่เกี่ยวข้อง) ทบทวนฟังก์ชันที่เซิร์ฟเวอร์อาจไปเรียก URL ตามอินพุต อ่านโค้ดและ User Story หน้าเว็บโหลดรูปในเบราว์เซอร์ตาม image_url จากฐานข้อมูล ไม่มีเส้นทางให้เซิร์ฟเวอร์ของแอปไปดึง URL ที่ผู้ใช้กำหนด ตรวจสำเร็จ ไม่เกี่ยวข้อง: ไม่มีฟังก์ชันฝั่งเซิร์ฟเวอร์ของแอปที่รับ URL จากผู้ใช้แล้วไปดึงต่อ การโหลดรูปเกิดในเบราว์เซอร์ของผู้ใช้ และผู้ใช้ทั่วไปตั้ง image_url ไม่ได้ js/app.js ใส่ image_url ใน &lt;img src&gt; ฝั่งไคลเอนต์; ไม่มีเซิร์ฟเวอร์พร็อกซีในคลัง ไม่มี เมื่อมีฟังก์ชันให้เซิร์ฟเวอร์ดึง URL ภายนอก ให้จำกัดโฮสต์ปลายทางแล้วตรวจซ้ำ —
09. File Upload และ Download
WSR-26 การอัปโหลดไฟล์ WSTG-BUSL-08; WSTG-ATHZ-01 (หมวดไฟล์) ทบทวนฟังก์ชันที่มีจริง สำรวจหน้า Production และโค้ด ไม่พบฟอร์มหรือ API อัปโหลด ตรวจสำเร็จ ไม่เกี่ยวข้อง: ระบบในขอบเขต US-101 ไม่มีฟังก์ชันอัปโหลดไฟล์ ไม่มี input type=file และไม่มีการเรียก Storage API ใน js/ ไม่มี เมื่อมีอัปโหลด ให้จำกัดชนิด ขนาด วิธีจัดเก็บ และการเข้าถึงก่อนเปิดไฟล์ —
WSR-27 การดาวน์โหลดหรือเปิดเอกสารส่วนตัว WSTG-ATHZ-01; WSTG-ATHZ-02 ทบทวนว่ามีเอกสารส่วนตัวที่ต้องตรวจสิทธิ์ก่อนเปิดหรือไม่ สำรวจเส้นทางที่เปิดสาธารณะ เอกสารที่เสิร์ฟเป็นเอกสารการสอน/ทดสอบ/ม็อกของโปรเจกต์ ไม่ใช่เอกสารของแต่ละผู้ใช้ ตรวจสำเร็จ ไม่เกี่ยวข้อง: ไม่มีเอกสารส่วนตัวหรือใบสั่งซื้อให้ตรวจสิทธิ์ก่อนดาวน์โหลด ไฟล์ที่เปิดได้เป็นเอกสารสาธารณะตามที่ทีมเผยแพร่ (ดู WSR-03) รายการเส้นทางใน WSR-03; User Story ไม่มีเอกสารรายบุคคล ไม่มี เมื่อมีเอกสารส่วนตัว ให้บังคับใช้สิทธิ์ฝั่งเซิร์ฟเวอร์ก่อนเปิดหรือดาวน์โหลด —
10. Business Logic
WSR-28 ราคาและการคำนวณสรุปรายการ (บทบาท: ผู้ใช้ทั่วไป) WSTG-BUSL-01; WSTG-BUSL-06 (หมวด); NIST SP 800-115 §4 ทบทวนโค้ดการคำนวณและข้อกำหนด รวมหลักฐานข้อจำกัดฝั่งฐานข้อมูล อ่าน js/cart.js (lineTotal, totals, formatBaht), ข้อ BA-C1/AC5 ใน User Story และข้อ CHECK price > 0 ใน db/001 ไม่มีเส้นทางส่งคำสั่งซื้อไปเซิร์ฟเวอร์ให้ตรวจการบังคับใช้ราคาฝั่งเซิร์ฟเวอร์ตอนชำระเงิน ตรวจสำเร็จ ผ่านในขอบเขตที่ตรวจ: ราคาที่แสดงมาจากฐานข้อมูลผ่าน API หน้าเว็บคำนวณราคารวมในเบราว์เซอร์ด้วยการแปลงเป็นสตางค์แล้วจัดรูปแบบทศนิยม 2 ตำแหน่ง ในขอบเขต US-101 ไม่มีการยืนยันคำสั่งซื้อหรือชำระเงิน จึงยังไม่มีจุดที่เซิร์ฟเวอร์ต้องบังคับใช้ราคาตอนทำธุรกรรม ข้อ CHECK price > 0 อยู่ในสคีมาสำหรับเส้นทางเขียนซึ่งผู้ใช้ทั่วไปใช้ไม่ได้ การที่ผู้ใช้แก้ตัวเลขในเบราว์เซอร์ได้มีผลแค่หน้าจอของตนเองและหายเมื่อรีเฟรช ตามออกแบบ (BA-C2) js/cart.js; US-101_user_story.md AC5, BA-C1, BA-C2; db/001 CHECK (price > 0) ไม่มี เมื่อมีสตอรีส่งคำสั่งซื้อหรือชำระเงิน ต้องให้เซิร์ฟเวอร์คำนวณราคาจากข้อมูลในฐานข้อมูลอีกครั้ง ห้ามเชื่อราคาส่งมาจากไคลเอนต์ แล้วตรวจซ้ำด้วยชุดทดสอบธุรกิจ บันทึกเป็นเงื่อนไขสำหรับสตอรีถัดไป ไม่ต้องแก้ US-101

11. API Security

WSR-41 ข้อมูลอ่อนไหวในไฟล์ที่เสิร์ฟสาธารณะและในคลังที่ deploy WSTG-INFO-05; WSTG-CRYP (หมวด) ทบทวนไฟล์สาธารณะและซอร์สแอป ตรวจ js/config.js, เอกสารที่เปิดบน Production และซอร์สแอป ตาม WSR-03 และ WSR-31 ไม่คัดลอกคีย์เต็มหรือคุกกี้ลงรายงาน ตรวจสำเร็จ ผ่านในขอบเขตที่ตรวจ: ไม่พบรหัสผ่าน โทเคนลับ ค่าเซสชัน หรือข้อมูลส่วนบุคคลในไฟล์ที่ตรวจ มีเพียง publishable key ซึ่งเป็นคีย์สาธารณะตามออกแบบ เอกสารที่เผยแพร่เป็นเอกสารการสอน/ทดสอบของโปรเจกต์ WSR-03, WSR-31; ไม่พบ sb_secret_ ในซอร์สแอป ไม่มี ไม่ต้องแก้เพิ่มจากข้อที่บันทึกใน WSR-04 (สื่อการสอนที่ยังไม่ถูก deploy) —
13. Client-Side Security
WSR-42 CORS ของโดเมนแอปและโดเมน API (บทบาท: ผู้ใช้ทั่วไป) WSTG-CLNT-07; WSTG-CONF-08 (หมวด CORS) อ่าน response header จากหน้าเว็บตามปกติและจาก GET API ที่แอปใช้ อ่าน Access-Control-Allow-Origin และหัวที่เกี่ยวข้องจากโดเมน Vercel และจากการตอบของ Supabase (รวมคำตอบ 401 ของราก REST) ตรวจสำเร็จ ผ่านในขอบเขตที่ตรวจ: โดเมนแอปมี Access-Control-Allow-Origin: * ซึ่งเป็นค่าที่พบบ่อยของไฟล์คงที่บน Vercel ไม่มีคุกกี้หรือเซสชันบนโดเมนนี้จึงความเสี่ยงต่ำ สอดคล้องข้อสังเกต S-07 ในรายงาน v1.0 (19 พ.ย. 2026) โดเมน API มี Access-Control-Allow-Origin: * เช่นกันและไม่ได้ใช้คุกกี้เป็นตัวยืนยันตัวตนของแอป (ใช้หัว Authorization) จึงไม่เข้าเงื่อนไข credentialed CORS ที่อันตรายในขอบเขตนี้ header หน้าแรกของ Vercel วันนี้; header ของ /rest/v1/ วันนี้มี Allow-Origin: * ; รายงาน v1.0 รายการ S-07 ไม่มี (ข้อสังเกต) ไม่จำเป็นต้องแก้ในขอบเขตปัจจุบัน หากภายหลังมีเซสชันแบบคุกกี้ข้ามโดเมน ต้องเลิกใช้ * ร่วมกับ credentials —
WSR-43 การป้องกัน Clickjacking ของหน้าเว็บ (บทบาท: ผู้ใช้ทั่วไป) WSTG-CLNT-09 อ่าน header ป้องกันการฝังเฟรม อ่าน X-Frame-Options และ CSP frame-ancestors จากหน้าแรกและไฟล์ static อ้างผลปิด S-05 ในรายงาน v1.1 ตรวจสำเร็จ ผ่านในขอบเขตที่ตรวจ: ข้อบกพร่อง S-05 ในรายงาน v1.0 ถูกปิดแล้วใน v1.1 (19 พ.ย. 2026, web v1.0.2) และยังยืนยันได้วันนี้ ทั้ง X-Frame-Options: DENY และ CSP frame-ancestors 'none' มีครบ header บน Production วันนี้; รายงาน v1.1 รายการที่ปิด S-05 ไม่มี ไม่ต้องแก้ —
WSR-44 การเก็บข้อมูลใน Browser Storage (บทบาท: ผู้ใช้ทั่วไป) WSTG-CLNT-12 ทบทวนโค้ดว่ามีการเก็บข้อมูลอ่อนไหวใน localStorage, sessionStorage หรือ cookie ของแอปหรือไม่ ค้นใน js/ และ index.html และทบทวนการเก็บตะกร้าตาม BA-C2 ตรวจสำเร็จ ผ่านในขอบเขตที่ตรวจ: ไม่มีการเก็บข้อมูลใน localStorage หรือ sessionStorage และโดเมนแอปไม่ตั้งคุกกี้ ตะกร้าอยู่ในหน่วยความจำเท่านั้น ไม่มีข้อมูลรับรองหรือข้อมูลส่วนบุคคลให้เก็บฝั่งไคลเอนต์ ไม่พบ localStorage/sessionStorage/document.cookie ใน js/ และ index.html; WSR-15, WSR-30 ไม่มี ไม่ต้องแก้ —
WSR-45 ส่วนประกอบฝั่งไคลเอนต์ภายนอก (บทบาท: ผู้ใช้ทั่วไป) WSTG-INFO-08; NIST SP 800-115 §4 ทบทวนสคริปต์ สไตล์ และรูปที่โหลดจากภายนอก อ่าน index.html, CSP และผลเดิม S-17 ในรายงาน v1.0 (19 พ.ย. 2026) ตรวจสำเร็จ ผ่านในขอบเขตที่ตรวจ: ไม่มีไลบรารีจาวาสคริปต์ภายนอก แอปใช้โมดูลในโปรเจกต์เอง โหลดภายนอกเพียง Google Fonts (CSS/ฟอนต์) ซึ่ง CSP อนุญาตไว้เฉพาะโฮสต์นั้น และรูปจาก URL แบบ https ตามข้อมูลเมนู (ม็อกใช้ placehold.co) ไม่สามารถใส่ SRI ให้ CSS ของ Google Fonts ได้สะดวกในทางปฏิบัติ ความเสี่ยงอยู่ในระดับที่ยอมรับได้สำหรับแอปนี้ index.html ลิงก์ fonts.googleapis.com; CSP style-src/font-src; ไม่มี &lt;script src&gt; ภายนอก; รายงาน v1.0 รายการ S-17 ไม่มี (ข้อสังเกต) ไม่จำเป็นต้องแก้ หากต้องการลดการพึ่งพาภายนอกให้โฮสต์ฟอนต์เองแล้วปรับ CSP แล้วตรวจซ้ำว่าหน้าเว็บยังแสดงผลได้ —
